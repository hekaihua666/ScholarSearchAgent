# 研问智搜论文 V3 证据台账

## 一句话论点

当受控引文扩展已经把更多相关论文带入候选池时，复杂学术查询需要显式建模必要条件、论文关系和引文方向，才能把新增候选稳定转化为 Top20 命中；单一通用相关性分数不足以完成这一转换。

## 术语统一

| 缩写 | 中文名称 | 在系统中的作用 |
|---|---|---|
| TRACE-Rank | 多路径融合基础排序 | 生成基础候选和现任 Top20 |
| SCGQ | 种子条件图查询 | 以高置信种子批量探索反向引文前沿 |
| QCF | 查询条件引文前沿 | 补充查询约束下的反向引用与正向参考文献 |
| REG | 关系证据图 | 分解条件合取、关系、方向、桥接和既有相关性证据 |
| 受保护残差路由 | Top20 局部替换机制 | 保护前 15 篇，每条查询最多替换 1 篇尾部结果 |
| LIVE--FROZEN--REPLAY | 冻结回放协议 | 隔离外部索引、网络和日期变化 |

## 主张—证据映射

| 论文主张 | 直接证据 | 结论强度 |
|---|---|---|
| REG 能将新增候选转化为 Top20 命中 | `reports/relational_evidence_graph_v18/05_dev20_metrics.csv`：TP 22→25；`08_holdout20_metrics.csv`：TP 17→18 | 开发集和一次性盲测均支持 |
| REG 未移除原有命中 | 开发集 `top20_lost=0`；盲测 `top20_lost=0`；校准冻结配置 `top20_lost=0` | 三个固定集合一致 |
| 受控前沿提高候选可达上限 | 开发候选 TP=27；盲测候选 TP=23，相对各自 Top20 的 22 和 17 均提高 | 支持“召回扩展有效” |
| 单一通用局部相关性不足 | v17 开发 TP 22→20，并损失 2 篇原命中 | 直接反例 |
| 逐条件通用语义瓶颈不是更优解 | ABER v19 校准 TP=24，而 REG v18 为 28 | 校准阶段拒绝 v19 |
| 当前剩余瓶颈是候选转化精度 | 盲测候选新增 6 个 TP，REG 只转化 1 个；12 次动作中 1 次增益 | 支持下一步研究方向 |
| REG 不增加 LLM 成本 | 盲测本地排序 27.28 秒；无新增 LLM/Token；外部检索平均 6.95 次/查询 | 成本记录支持 |
| 实验可以逐条回放 | `holdout_state.json` 与报告记录 20/20 LIVE–REPLAY 身份序列一致 | 复现证据 |

## 冻结参数

- 权重：按 default、taxonomy、survey、usage 四类关系族冻结；
- `score_floor=0.62`；
- `margin=0.10`；
- `max_promotions=1`；
- `protect_head=15`；
- 配置来源：`configs/relational_evidence_graph_v18/calibration_freeze.json`。

## 失败实验保留

v17、ABER v19 以及未形成稳定迁移收益的探索性 v20 不进入生产冠军路径。它们在论文中只承担消融和反证作用：v17 说明通用完整查询相似度会误换，v19 说明把问题拆成逐条件硬瓶颈仍不能表达论文角色与集合互补性。
