# HELIOS：假设—证据闭环的信息增益科研检索算法

## 1. 算法定位

HELIOS（Hypothesis–Evidence Loop with Information-gain Optimized Search）面向复杂科研问题，不再把检索目标定义为“找到与问题语义相似的论文”，而是定义为：

> 在有限检索预算内，为科研问题中的每一项关键约束寻找可核验的论文证据，并显式发现尚未闭合的证据缺口、相互矛盾的结论与技术演进关系。

系统最终输出的不是普通 Top-K 列表，而是一个带证据、缺口、争议与演进路径的“研究问题证据闭环”。

## 2. 科研问题超图

将用户问题解析为科研约束超图：

\[
Q=(V,R,W,Z)
\]

- \(V\)：原子约束，如研究对象、任务、方法、数据、条件、时间、结论；
- \(R\)：约束之间的关系，如“方法用于任务”“结论成立于条件”；
- \(W\)：各约束的重要性；
- \(Z\)：必须满足、偏好满足、必须排除三类逻辑极性。

例：“寻找 2021 年后、无需标注、适用于多变量时间序列且能够解释异常根因的方法”会被拆为：

1. 时间：2021 年后；
2. 监督条件：无需标注；
3. 数据类型：多变量时间序列；
4. 任务：异常检测；
5. 能力：根因解释。

## 3. 证据对齐与反事实验证

对论文 \(p\) 的正文证据片段 \(e\) 与约束 \(v_i\) 计算支持、矛盾和未知概率：

\[
C(e,v_i)=P(\mathrm{support})-P(\mathrm{contradict})
\]

论文不能仅凭标题或摘要相似就被判定相关。系统还执行反事实删除：移除最强证据片段后，如果论文对该约束的支持度几乎不变，说明模型可能只是在依赖主题相似性，降低其可信分。

\[
CF(p,v_i)=F(p,v_i)-F(p\setminus e^*,v_i)
\]

最终的证据可信度同时考虑直接支持、证据位置、跨片段一致性和反事实贡献。

## 4. 证据缺口驱动的主动检索

定义第 \(i\) 个约束的未闭合缺口：

\[
g_i=w_i\left(1-\max_{p\in S} C(p,v_i)\right)
\]

检索动作不再按固定流程执行。系统从关键词检索、语义检索、方法别名扩展、前向引用、后向引用、作者追踪、相似论文、全文片段检索中选择下一步动作。动作价值为：

\[
a^*=\arg\max_a
\frac{\mathbb{E}[\Delta Cov+\lambda\Delta Rec+\mu\Delta Div+\nu\Delta Path-\rho Drift]}{Cost(a)}
\]

其中：

- \(\Delta Cov\)：预计增加的约束覆盖；
- \(\Delta Rec\)：预计召回增益；
- \(\Delta Div\)：预计增加的方法多样性；
- \(\Delta Path\)：预计补全的技术演进路径；
- \(Drift\)：查询漂移风险；
- \(Cost(a)\)：时间、API 与模型调用成本。

当所有必需约束达到阈值，或继续检索的边际信息增益低于成本阈值时，算法自动停止。

## 5. 最小充分证据集

最终结果不按单一相关性分数简单排序，而是在数量预算 \(K\) 下选择最小充分证据集：

\[
S^*=\arg\max_{|S|\le K}
\left[
\sum_i w_i\max_{p\in S}C(p,v_i)
+\alpha L(S)+\beta B(S)+\gamma T(S)-\delta R(S)
\right]
\]

- \(L(S)\)：技术演进链完整度；
- \(B(S)\)：支持与反对证据的平衡度；
- \(T(S)\)：来源可信度；
- \(R(S)\)：论文之间的冗余。

其中约束覆盖部分属于子模覆盖目标，可使用贪心算法获得可解释、稳定且高效的近似解。

## 6. 面向用户的四项输出

1. **论文结果**：最小充分证据集，而非二十篇相似论文；
2. **证据矩阵**：每篇论文满足哪些条件，证据位于哪里；
3. **缺口雷达**：当前问题中哪些条件仍没有可靠论文支持；
4. **演进与争议图**：奠基、发展、分叉、反驳、前沿及缺失桥梁。

## 7. 与现有路线的关键区别

- 普通混合检索优化“相关性”；HELIOS 优化“科研约束的证据闭合度”。
- PaSa 的 Crawler/Selector 主要优化相关论文发现；HELIOS 显式决定“下一步应补哪个证据缺口”。
- 引文图 RAG 主要将引用关系用于扩展或组织；HELIOS 将引用动作放进信息增益决策，并追踪其边际贡献。
- 工作流智能体学习如何执行搜索流程；HELIOS 的停止、转向和扩展由可计算的证据缺口与成本共同控制。
- 普通重排判断“像不像”；HELIOS 要求候选论文给出可定位证据，并通过反事实删除降低伪相关。

## 8. 新指标

### Evidence Closure@K（证据闭合率）

\[
EC@K=\frac{\sum_i w_i\max_{p\in TopK}C(p,v_i)}{\sum_i w_i}
\]

### Unsupported Acceptance Rate（无证据接纳率）

被系统列为满足约束、但正文中没有可核验证据的论文比例，越低越好。

### Gap Discovery Accuracy（缺口识别准确率）

系统指出“证据不足”的约束中，经人工复核确实缺少充分证据的比例。

### Search Utility per Cost（单位成本检索效用）

\[
SUC=\frac{\Delta EC+\lambda\Delta Recall}{\text{耗时}+\eta\cdot\text{API成本}}
\]

## 9. 必须完成的实验

1. AutoScholarQuery：Recall@5/20、MRR、nDCG；
2. LitSearch：真实科研问题的检索表现；
3. 自建多约束测试集：证据闭合率、无证据接纳率和缺口识别准确率；
4. 消融实验：去掉问题超图、主动策略、反事实证据、引文路径、多样性约束；
5. 等预算对比：固定 API 次数和固定时间，比较主动检索与固定流水线；
6. 人工盲评：相关性、可解释性、科研可用性与节省时间。

在实验结果产生前，不预设“领先”结论；只有完整系统相对强基线获得稳定增益后，才能将其写成项目的算法贡献。
