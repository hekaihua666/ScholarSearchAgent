# 研问智搜：决赛重构方案与开源项目调研

## 1. 决赛目标与硬指标

本项目对应华为赛题三“科研场景下复杂学术查询的智能论文搜索与推荐”。自动评测重点为：F1 Score 70%、运行效率 20%、结构化结果 10%；总成绩由竞赛得分 60% 和专家评分 40% 构成。专家评分关注创新性、落地可行性和泛化性。决赛展示还需要完整说明开发流程、技术概要、创新点和应用价值。

因此重构不以“堆功能”为目标，而以四个可验证结果为主线：

1. 公开基准上的 F1、Recall@20、Precision@20 明确优于 BM25 和单轮检索基线；
2. 每次检索的 API 次数、Token、耗时和降级路径可追踪；
3. 推荐理由能回到标题、摘要、DOI 或引文关系，不用模型记忆补造事实；
4. 在无 Key、单一数据源限流、网络波动时仍能现场运行。

## 2. 同类优秀项目调研结论

| 项目 | 值得吸收的设计 | 不直接照搬的部分 |
|---|---|---|
| [PaSa](https://github.com/bytedance/pasa) | Crawler/Selector 分工；把“继续搜什么、读什么、选什么”建模为连续决策；RealScholarQuery/AutoScholarQuery 评测 | 7B 模型训练和 PPO 成本高，不适合当前笔记本现场部署 |
| [SPAR](https://github.com/xiaofengShi/SPAR) | RefChain 查询分解；树式迭代；相关论文的参考文献扩展；明确停止条件 | 原工程依赖和搜索路径较重，不能整体移入当前轻量系统 |
| [PaperScout](https://github.com/AgentR1/PaperScout) | 将搜索视为多轮决策过程；用训练提升小模型搜索策略；重视跨基准表现 | 训练复现和模型权重不作为本轮重构前置条件 |
| [Ai2 Scholar QA](https://github.com/allenai/ai2-scholarqa-lib) | 元数据过滤、关键词检索与全文片段检索结合；cross-encoder 重排；证据聚合后再生成 | 依赖超大自有语料索引，当前系统无法原样复现 |
| [PaperQA2](https://github.com/Future-House/paper-qa) | 检索—证据收集—回答三阶段；上下文摘要、LLM 重排、元数据核验和本地全文索引 | 更偏“对已有 PDF 问答”，需转换为开放网络论文发现流程 |
| [ScholarLoop](https://github.com/124-creator/ScholarLoop) | BM25/稠密检索/交叉编码器融合；证据卡和字段级核验；基准、消融和显著性报告完整 | 公开快照不含全部训练语料和缓存，指标不能直接作为本项目结果引用 |
| [AstaBench](https://github.com/allenai/asta-bench) | 科研 Agent 的任务化、可复现评测思路 | 用作评测框架参考，不将全部任务并入比赛系统 |

吸收原则：借鉴公开方法和工程模式，重新实现与赛题匹配的模块；保留来源、许可证和对比说明，不复制他人成果后改名。

## 3. 当前版本的主要问题

1. OpenAlex 原先按引用量排序，容易把“著名但离题”的论文推到前面；现已改为相关性排序。
2. 多数据源原先主要是故障降级关系，不是真正的多源召回；第一轮已加入独立 arXiv 补充通道。
3. 去重时只保留一条命中记录，丢失“同一论文被多个子查询、多数据源命中”的强证据。
4. 固定四维线性排序对复杂约束覆盖不足，也没有结果多样性控制。
5. LLM 相关性判断曾直接删除候选，容易损害召回率和 F1；现改为软评分，不硬删除 Top-20。
6. 尚无正式基准评测、消融实验、错误案例库和统计显著性检验，这是决赛前最大的材料缺口。

## 4. 自研算法：TRACE-Rank

TRACE-Rank 是面向复杂学术查询的轻量排序模型，由六类信号组成：

\[
S(p,q)=0.38S_{lex}+0.24S_{rrf}+0.16S_{constraint}+0.10S_{authority}+0.06S_{fresh}+0.06S_{meta}
\]

- `S_lex`：标题双权重、摘要单权重的查询词匹配；
- `S_rrf`：对子查询、数据源和轮次的命中使用 Reciprocal Rank Fusion；
- `S_constraint`：主题、方法、任务、领域四类约束的覆盖率；
- `S_authority`：按论文年龄归一化的年均引用影响力，避免只偏向老论文；
- `S_fresh`：新近性；
- `S_meta`：摘要、作者和 DOI 的元数据完整性。

随后使用 MMR 风格的贪心选择降低近重复结果。对前 20 篇论文再进行一次批量 LLM 严格相关性打分：

\[
S_{final}=0.55S_{TRACE}+0.45S_{LLM}
\]

LLM 评分只参与软重排和“高度相关/部分相关”分层，不再直接删除 Top-20，以保护召回率。该设计同时借鉴 RRF、约束覆盖、LLM rerank 和多样性选择，但组合方式、降级逻辑和工程实现均针对本赛题重新设计。

## 5. 目标架构

```text
复杂自然语言查询
  -> 查询约束解析与可靠性门控
  -> 查询计划（核心 / 方法 / 任务 / 反向排除 / benchmark）
  -> OpenAlex + arXiv + Semantic Scholar/Crossref 多源召回
  -> 统一论文实体、命中轨迹和 DOI 级去重
  -> TRACE-Rank 初排
  -> 引文前向/后向扩展 + 动态停止
  -> 批量 LLM 约束重排
  -> Top-20 + 高度/部分相关分层
  -> 证据卡、关系图、检索轨迹和成本指标
```

## 6. 迭代路线

### P0：评测闭环（最高优先级）

- 接入 LitSearch、RealScholarQuery/PaSa 可用测试集；
- 实现 Precision、Recall、F1、Recall@20、NDCG@20、平均耗时、API/Token 成本；
- 建立 BM25、单轮 OpenAlex、旧四维排序、TRACE-Rank 的同条件基线；
- 保存逐查询结果、失败原因和可复现实验配置。

### P1：召回与排序

- 对 OpenAlex、arXiv、Semantic Scholar 进行真正并行的多源召回；
- 引入前向参考文献和后向被引论文扩展；
- 添加可选本地 embedding/cross-encoder，CPU 不可用时自动降级；
- 用公开验证集学习融合权重，不手调后直接宣称有效。

### P2：可信证据与科研工作流

- 推荐理由标出由标题、摘要或元数据支持的字段；
- DOI、作者、年份进行跨源一致性核验；
- 支持收藏、对比、BibTeX/RIS 导出、检索历史和阅读路线；
- 对无法核验的内容明确标记“待核验”。

### P3：界面与决赛展示

- 首页聚焦查询输入和示例，不展示无意义大屏数字；
- 结果页按“结论—推荐论文—证据—检索过程—指标”组织；
- 加入普通模式/专家模式，默认界面简洁，技术细节可展开；
- 准备固定离线演示样例、实时查询样例和故障降级样例。

### P4：论文和答辩材料

- 论文按问题定义、方法、实验、消融、误差分析、成本和局限性重写；
- 所有指标从自动评测产物回填，不使用无法复现的宣传数字；
- PPT 重点展示一个真实复杂查询从输入到证据链的全过程。

## 7. 本轮已经落地

- 新增 `backend/trace_rank.py`；
- 实现多命中保留、RRF、查询约束覆盖、时间归一化引用、多样性重排和关系图数据；
- OpenAlex 改用相关性排序；
- 第一轮加入独立 arXiv 召回；

- 新增基础单元测试并完成真实网络查询验证。
