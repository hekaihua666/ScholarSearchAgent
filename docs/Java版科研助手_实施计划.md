# Java 版科研助手实施计划

更新：2026-10-16 11:18。状态：计划已建立，Java 工程尚未创建。

执行顺序：先完成独立前后端 Web 应用，再评估 MCP / 插件接入。本文是该项目后续实施的主清单；项目状态文件保存当前执行位置。

## 1. 最终做成什么

做成一个通过浏览器使用的科研文献检索与个人知识库助手，完整流程为：

用户登录 → 输入研究问题 → 搜索真实论文 → 查看来源和推荐理由 → 收藏论文、访问可用全文 → 上传 PDF → 异步解析和建立索引 → 基于资料问答 → 查看引用原文和对应页码。

Java 后端负责真实业务、检索与 AI 能力；前端提供可操作页面。后续插件复用业务 Service，不把页面逻辑搬进插件。

### 1.1 Web 首版范围

- 科研问题检索、结果去重与基础排序、真实论文来源、可获取的全文链接、BibTeX 导出。
- 用户注册登录、个人收藏、检索历史、私有资料权限。
- 文字型 PDF 上传、状态查询、失败重试、资料查看与删除。
- 文档解析、分段、向量化、权限过滤后的检索、带引用问答、流式输出、对话历史。
- 一次受控的补充搜索，保留实际调用与停止原因；不承诺自由自主执行任意任务。
- 可以复现的启动方法、测试与评测记录、实际浏览器验收、部署说明。

### 1.2 后续范围

- Word / Markdown 导入保留在 Web v1.1：原 Java 总规划包含这些格式，本次先用文字型 PDF 完成首版闭环。
- 扫描 PDF 的 OCR、复杂表格与公式理解、自动综述生成，在基础问答验收后另定范围。
- 高级引文图、交叉编码重排、现有比赛版本的全部选择器，按测量收益逐项引入。
- Web 稳定后才安排 MCP、Codex / Harness 适配和宿主本地文件操作。
- 当前不并行引入微服务、复杂多 Agent、Kubernetes、额外消息队列或多个向量数据库。

### 1.3 第一版的完成定义

由两个测试用户在浏览器完成上述主流程；甲用户不能访问乙用户资料；回答的引用能打开实际原文；文档失败可查可重试；重启后资料和任务状态仍可恢复；真实模型与降级路径分别标识；启动和验证过程有记录。

## 2. 如何一步一步执行

1. 每轮默认锁定一个任务编号，说明本轮输入、修改范围和验收方法。
2. 按最小可运行功能实现；新增代码写清关键步骤的中文注释，并解释设计取舍。
3. 完成后交付可运行结果、必要测试或人工检查证据，以及当前限制。
4. 遇到报错先定位根因；修复当前阻塞后再叠加后续功能。
5. 任务验收完成才勾选；不把文档支持、模拟数据或旧 Python 结果当作 Java 实现证据。
6. 更新本清单和 codex-continuity/PROJECT_STATE.md，只保留一个当前执行位置。
7. 不要求先刷完课程。每个阶段只补充本阶段需要的原理与用法，并能脱离生成代码解释流程。

若模型凭据或服务暂不可用，可以先推进不依赖模型的 P1—P3，同时保留 P0-03 未完成状态；进入 P4 的真实模型功能和 P5 的向量入库前必须补齐验证。独立工作可以继续，缺失依赖不能通过 Mock 伪装完成。

## 3. 工程位置与技术方案

### 3.1 目录与边界

默认新工程根目录：java-web（相对于项目根目录）。

新目录内分别放 backend、frontend、deploy、docs、evaluation；Java 工程独立使用 Git。现有根目录下的 backend、frontend、tests、configs、reports 保留为 Python 参考版本，不覆盖或改名。

后端按 auth、search、paper、document、chat、common 等业务组织代码。Controller 只处理 HTTP 参数与响应，Service 承担业务流程，客户端与 Mapper 承担外部调用和数据访问。先做单体，不为未来插件预建通用适配框架。

### 3.2 默认技术选择

| 部分 | 方案 | 使用边界 |
|---|---|---|
| 前端 | Vue 3、TypeScript、Vite、Vue Router、Element Plus | 先做搜索页，逐步加入其他页面；不先做复杂前端架构 |
| 后端 | Spring Boot、Spring MVC、Bean Validation | REST 接口、统一异常、业务 Service |
| AI | Spring AI | 对话、结构化输出、Embedding、RAG；聊天和向量化分别验证 |
| 数据 | MySQL、MyBatis-Plus、版本化数据库迁移 | 保存用户、论文、资料、任务、对话与来源元数据 |
| 缓存与限流 | Redis | 缓存、会话或限流；任务最终状态以数据库为准 |
| 检索 | Elasticsearch | 文档片段、向量与元数据过滤；后续按评测需要加入关键词融合 |
| 身份权限 | Spring Security | 首版采用 Session 与 HttpOnly Cookie，保留 CSRF 防护；开发代理和部署同源 |
| PDF | Spring AI PDF Reader / PDFBox | 首先按页解析文字型 PDF，保留真实页码 |
| 异步任务 | 有界线程池、数据库任务记录与恢复机制 | 首版不引入 MQ；线程池本身不承担任务持久性 |
| 回答推送 | SSE，前端通过 fetch 读取流 | 支持携带 POST 请求体；不假设原生 EventSource 能发送 POST |
| 构建与验证 | Maven Wrapper、前端 lockfile、JUnit、MockMvc、必要集成测试 | 测试依赖版本跟随兼容组合冻结 |
| 运行部署 | Docker Compose、反向代理 | 开发阶段只启动当前需要的服务，ES 在入库阶段加入 |

这些是计划默认值，不代表已经安装、配置或通过集成测试。

目标：避免工程写到一半才发现依赖不兼容、没有向量化模型或目标范围不断扩大。

- [ ] P0-02 冻结候选依赖表。核对 Boot、Spring AI、MyBatis-Plus、数据库驱动、ES 客户端、前端工具链；将实际编译验证安排在 P1。产物：dependency-matrix.md。验收：每个组件有明确版本来源与验证状态，区分候选和已验证。
- [ ] P0-03 验证模型方案。对话模型和 Embedding 分别做最小真实请求；记录模型标识、向量维度、超时、计量方式和配额；密钥仅置于本地环境。产物：model-connectivity.md。验收：两类请求各有脱敏结果；若尚不可用，明确阻塞，不能用 Mock 通过 AI 验收。
- [ ] P0-04 固定首版场景与样例。明确搜索、收藏、上传、问答页面和输入输出，先选 20 条论文检索问题、30 条问答验收案例，并标明开发与保留样例。产物：requirements.md、evaluation/README.md。验收：每类场景有预期行为；无法回答、越权、注入与外部失败都有案例；参考答案只能依据实际可用资料建立。

## 6. P1：建立前后端最小工程

目标：先得到可启动、可调试、能真实联通的工程，暂不实现复杂检索。

- [ ] P1-01 创建 java-web 独立工程。建立前后端、部署、说明和评测目录，初始化 Git 与忽略规则。产物：工程结构、README、无凭据配置示例。验收：不覆盖 Python 目录，不提交缓存、用户 PDF、运行数据和密钥。
- [ ] P1-02 建立 Java 骨架。加入健康检查、参数校验、统一异常、请求编号和必要日志；只接入当前需要的依赖。产物：可启动后端与最小接口。验收：健康检查正常，错误参数有明确响应，启动失败能定位根因。
- [ ] P1-03 建立 Vue 页面与 API 调用。使用开发代理访问 Java，显示真实健康状态；统一处理加载、空态和错误。产物：最小首页与请求封装。验收：浏览器实际请求 Java，后端停止时页面展示真实错误。
- [ ] P1-04 配置独立 MySQL / Redis 运行环境和数据库迁移。使用专属容器、数据卷和配置，不复用或清理其他项目的数据。产物：最小 Compose、迁移脚本、启动说明。验收：连接、读写和重启后数据保留通过。
- [ ] P1-05 验证与冻结依赖。完成后端构建、前端构建、数据库连接和基础集成检查；保留 Wrapper 与 lockfile。产物：依赖冻结表与阶段记录。验收：候选组合实际通过；新增空工程在另一终端按 README 可重复启动。

阶段检查：从浏览器到 Controller、Service，再到配置与数据库的调用路径能够解释；本阶段才把通过验证的版本标为已冻结。

## 7. P2：完成真实论文搜索

目标：先得到一个真正可用的论文搜索页面，不依赖大模型也能完成基础检索。

- [ ] P2-01 定义论文与搜索数据结构。包含内部 ID、外部标识、标题、作者、年份、摘要、来源、链接、来源排名与检索状态。产物：DTO、领域对象与接口契约。验收：区分论文实体、来源记录与一次搜索结果，不把排序分数当作正确概率。
- [ ] P2-02 接入主数据源和备用来源。先实现 OpenAlex，再按场景增加 arXiv 补充或回退；配置连接 / 读取 / 总体超时和有界重试。产物：客户端与模拟失败案例。验收：真实论文可返回；限流、超时、空结果分别处理；部分失败时能保留已有结果。
- [ ] P2-03 实现保守去重与基础排序。优先使用 DOI / arXiv 等稳定身份，标题归一化作辅助；保留上游相关性，加入可解释的基础匹配；冲突身份不盲目合并。产物：去重与排序 Service。验收：同篇跨来源合并，明显不同论文不误合并，每篇保留来源证据。
- [ ] P2-04 完成搜索页面。支持输入、基本时间条件、结果卡片、摘要、来源、论文页、可用全文链接与 BibTeX 导出。产物：可操作页面。验收：链接来自真实元数据；无全文时明确说明；空结果与全部来源失败分开显示。
- [ ] P2-05 做一次端到端检查。覆盖正常输入、空输入、无结果、超时、来源失败和重复记录；核对浏览器渲染。产物：请求样例、必要自动化检查与浏览器记录。验收：从用户输入到真实论文展示的闭环完成，模拟结果明确标识。

阶段检查：能说明候选论文来自哪里、为什么被合并、为什么排在前面。多查询 RRF 融合留到 P4；不先搬运全部比赛选择器。

## 8. P3：用户、收藏与数据归属

目标：在引入私有全文前，先建立可验证的用户与权限基础。

- [ ] P3-01 实现注册、登录、退出与当前用户。密码使用安全哈希，Session Cookie 使用合理属性；保留 CSRF 防护和登录失败限制。产物：认证接口与登录页面。验收：成功 / 失败 / 未登录 / 退出后访问行为正确，日志不泄露密码与会话凭据。
- [ ] P3-02 实现论文持久化与个人收藏。论文元数据和收藏关系分开，收藏按用户与论文唯一约束。产物：表结构、收藏页面与增删查接口。验收：重复收藏幂等，用户只能操作自己的收藏。
- [ ] P3-03 保存检索历史并加入必要缓存。公共论文缓存与用户私有历史分开；缓存键包含影响结果的条件和版本。产物：历史页面与缓存规则。验收：不同用户不串数据，冷 / 热缓存行为可观察，配置改变后不会错误复用结果。
- [ ] P3-04 做两用户权限检查。使用用户甲与用户乙验证收藏、历史及后续资料接口的权限契约。产物：权限用例与集成验证。验收：修改请求中的用户 ID 或资源 ID 不能取得他人数据，身份从服务端认证上下文取得。

阶段检查：能说明登录状态怎样得到、数据归属怎样检查，以及为什么页面隐藏按钮不能代替服务端鉴权。

## 9. P4：AI 查询理解与受控迭代检索

目标：让系统能处理中文科研需求，并解释检索决策；执行范围始终受代码与预算约束。

- [ ] P4-01 接入真实聊天模型与结构化输出。统一模型适配、输出 DTO 校验、超时和错误分类。产物：模型客户端与可回放响应样例。验收：合法响应可用，格式错误与调用失败可定位；缺少模型时明确降级，不伪造已发生的调用。
- [ ] P4-02 实现查询拆解。抽取主题、方法、任务、领域与时间要求，生成有限条英文检索式；保留原问题和必要规则锚点。产物：查询计划对象与前端计划说明。验收：检索式与原需求相关，时间过滤一致，非法或漂移输出被限制。
- [ ] P4-03 执行有界多查询检索。限制子查询数、并发、重试和总调用预算，记录成功、失败与跳过。产物：检索编排 Service。验收：外部服务失败不无限重试，预算能终止额外搜索，调用次数来自实际事件。
- [ ] P4-04 加入基础融合和一次补搜。使用 RRF、条件匹配和必要的多样性选择；根据覆盖缺口决定是否执行至多一次补充搜索，再合并结果。产物：排序解释与停止记录。验收：能用具体论文手工核对主要分数；无新收益或预算不足时停止；阈值只在开发样例调节。
- [ ] P4-05 完善过程和成本展示。记录模型标识、阶段耗时、真实用量、来源调用、缓存命中和降级原因；用户界面只展示有用信息。产物：过程视图与脱敏诊断记录。验收：未调用模型时不显示固定调用数；未知用量标为未知；估算成本和服务商计费区分。

阶段检查：能解释工具为何被使用、失败如何处理、何时停止，以及推荐理由依据什么。高级引文关系模块仅在后续对照实验显示收益后引入。

## 10. P5：PDF 上传与可恢复的知识库入库

目标：让一份资料从上传到可检索的全过程可观察、可重试，并保留原文定位信息。

- [ ] P5-01 实现受控上传与资料记录。先支持文字型 PDF；检查类型、大小和页数限制，使用服务端生成的文件标识与私有存储目录。产物：上传接口、资料表与文件存储。验收：上传立即返回资料与任务编号，不等待全部解析；文件归属从认证上下文取得；原始文件名不能决定存储路径。
- [ ] P5-02 按页解析与分段。提取正文、原始页序号和片段，保留 documentId、chunkId、pageStart、pageEnd、chunkIndex、内容哈希与解析版本。产物：可检查的解析结果与分段策略。验收：引用片段能回到真实 PDF 页；无法提取文字、加密或损坏文件返回明确状态；不把扫描件成功读取成空知识库。
- [ ] P5-03 实现持久任务与有界执行。数据库保存任务状态、尝试次数、下次重试时间与运行租约；线程池执行，启动时恢复可重试任务，超时租约可回收。产物：任务 Service 与恢复逻辑。验收：处理中重启后不会永久停在运行状态；重复执行不会重复生成片段；重试达到上限后停止并记录原因。
- [ ] P5-04 接入 Embedding 和 ES 索引。校验模型返回维度，用稳定 chunkId 写入向量、正文及 ownerId、documentId、indexVersion 等元数据。产物：索引映射与写入流程。验收：批次失败可重试，重复写入幂等，模型或维度变更必须重建索引而非混写。
- [ ] P5-05 完成状态流转与可见性控制。资料经历上传、解析、索引、就绪或失败等状态；完成全部必要写入后才标记就绪，任务状态以 MySQL 为准。产物：状态查询与任务页面。验收：部分索引不作为完整资料参与问答；用户能看到当前阶段和可理解的失败原因，不使用定时器伪装真实进度。
- [ ] P5-06 实现资料查看、下载、重试和删除。所有入口检查归属；删除先使资料在业务上不可访问，再清理片段、向量和文件；查询结果再次核对当前就绪 / 删除状态。产物：资料管理页面与接口。验收：两用户隔离通过，失败资料可重试，删除中的资料和旧缓存不能继续进入问答上下文。

阶段检查：用同一份文件执行成功、重复提交、失败重试和重启恢复；核对数据库、文件和 ES 的记录对应关系。首版用持久任务解决恢复，不以加入 MQ 代替一致性设计。

## 11. P6：RAG、引用溯源与流式对话

目标：先检索允许访问的原文证据，再生成可核对的回答。

- [ ] P6-01 单独验收知识库检索。限定当前用户和选定文档，先实现向量检索，并返回原文片段与页码；在小样例比较检索数量与阈值。产物：证据检索 Service。验收：能在不调用聊天模型时找到对应原文；权限过滤发生在返回正文前，不依赖模型遵守提示词。
- [ ] P6-02 构建受控回答流程。输入包括问题、有限历史和允许使用的证据；外部文档当作资料处理，不提升为系统指令；无有效证据时明确说明依据不足。产物：RAG Service 与提示词版本。验收：正常、无答案和包含诱导指令的文档样例分别验证，模型不能通过工具参数绕过服务端权限。
- [ ] P6-03 实现引用对象与校验。引用由服务端从本次检索结果映射到 documentId、chunkId、页码和原文，不接受模型凭空生成来源。产物：引用结构与校验规则。验收：每个引用 ID 可解析且属于当前授权证据；人工核查引用是否真正支持对应结论，不能只验证链接存在。
- [ ] P6-04 实现流式回答与中断处理。明确开始、文本片段、引用、完成、失败等事件；前端可停止，服务端及时结束或取消下游调用，并保存已知状态。产物：SSE 接口与流式聊天组件。验收：真实逐步输出，断开和失败不会显示成完整成功，限制请求时长与输出长度。
- [ ] P6-05 保存对话与上下文。会话、消息归属用户；记录消息状态、引用快照和模型用量；限制送入模型的历史长度。产物：会话 / 消息存储与历史页面。验收：刷新后可恢复，其他用户无法读取，生成失败与用户取消可区分，历史不会无限进入上下文。
- [ ] P6-06 完成浏览器引用与多文档问答。可选择一个或多个已就绪文档，查看引用原文并打开对应 PDF 页。产物：问答页面与资料跳转。验收：同一问题的回答、引用和原文页能逐一核对；尚未实现的图表 / 公式理解不当作已完成能力展示。

阶段检查：能解释检索与生成的分工、切分和检索参数怎样影响结果，以及引用 ID 正确为什么仍不等于回答事实正确。

## 15. 最小数据与接口草案

该草案用于分阶段落地，只有相应功能开始时才创建对应表和接口；不在 P1 一次性堆齐所有模块。

### 15.1 数据归属

| 数据 | 最小作用与约束 |
|---|---|
| user | 登录身份、密码哈希与状态 |
| paper / paper_identifier | 规范论文与外部标识，保留来源；不把全局论文与用户收藏混为一表 |
| user_paper | 用户收藏关系；userId、paperId 唯一 |
| search_history | 用户查询、实际模式和结果摘要；避免保存无必要的模型原始输出 |
| document | ownerId、文件存储标识、哈希、状态与处理版本，可关联 paperId |
| document_chunk | 稳定片段 ID、正文、文档归属、页码与版本；ES 为可重建检索索引 |
| processing_task | 处理阶段、重试次数、错误类型、下次运行时间和运行租约 |
| conversation / message | 用户会话、消息状态、模型信息、实际用量与引用快照 |

删除资料、重建索引和更换 Embedding 模型，都必须考虑旧任务、旧向量与旧缓存。状态与版本检查放在 Service 中，不能仅靠前端控制。

### 15.2 接口方向

| 功能 | 接口草案 |
|---|---|
| 健康与登录状态 | GET /api/health、GET /api/me |
| 登录与退出 | POST /api/auth/register、POST /api/auth/login、POST /api/auth/logout；按所选 Session / CSRF 机制完善契约 |
| 搜索 | POST /api/search；返回 searchId、论文、来源与实际执行状态 |
| 收藏 | GET /api/favorites、PUT /api/favorites/{paperId}、DELETE /api/favorites/{paperId} |
| 历史 | GET /api/search-history |
| 上传与资料 | POST /api/documents、GET /api/documents、GET /api/documents/{id} |
| 文件与任务 | GET /api/documents/{id}/file、GET /api/tasks/{id}、POST /api/documents/{id}/retry、DELETE /api/documents/{id} |
| 对话 | POST /api/conversations、GET /api/conversations/{id}/messages、POST /api/conversations/{id}/messages（SSE） |

接口编号、分页与错误结构在对应阶段冻结；不要让聊天模型提供的 ownerId、文档 ID 或路径代替服务端授权。

## 16. 需要特别区分的事实

- 找到论文元数据，不等于拿到全文；只有实际可获取的全文才能下载，只有实际导入的内容才能用于全文问答。
- 首版提供可用全文链接与用户上传。后续若增加服务端自动下载，需要来源与重定向校验、超时 / 大小限制和文件类型验证；不能直接让用户给任意 URL 由服务端读取。
- 论文标题 / 摘要总结与全文 RAG 是不同能力，界面和报告分别标识。
- 模型建议、排序分数和条件覆盖值都不是论文正确性证明，引用关系也不自动证明方法满足要求。
- Session、缓存与任务状态都可用 Redis 加速，但任务恢复不能只依赖内存队列或过期键。
- 开发、回归和保留样例用途分别记录；小样本改善不宣传为通用优越性。
- Java 主线保持真实业务实现；Python 可继续用于旧版对照和评测脚本，不为迁移而重写所有实验工具。
