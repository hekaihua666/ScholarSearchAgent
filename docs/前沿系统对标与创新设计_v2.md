# 研问智搜前沿系统对标与创新设计 v2

## 一、2025—2026 年前沿路线

当前复杂学术检索已从“查询改写 + 单轮搜索”转向可自主选择工具的多轮 Agent。

| 系统 | 核心路线 | 优势 | 对本项目的启发 |
|---|---|---|---|
| [PaSa（ACL 2025）](https://aclanthology.org/2025.acl-long.572/) | Crawler + Selector；搜索与引文网络遍历；RL 训练 | 在 RealScholarQuery 上显著提高 Recall@20/50 | 搜索与筛选必须分离；引文网络是间接论文反查的关键 |
| [SPAR](https://arxiv.org/abs/2507.15245) | RefChain、树式检索、查询演化、引用扩展 | 无需训练，模块化强 | 采用查询路径和引文路径双通道，但必须控制树爆炸 |
| [PaperScout](https://github.com/AgentR1/PaperScout) | 自适应 Search/Expand 决策；PSPO 过程奖励 | 用更少工具调用取得更高召回效率 | 固定两轮流程应升级为根据过程状态动态决策 |
| [ScholarQuest](https://www.alphaxiv.org/abs/2606.20235) | 面向开放文献环境的意图分类与效率评测 | 揭示 PaSa/SPAR 引文扩展调用多、PaperScout 更聚焦，也指出范围约束查询仍困难 | 不能只追求候选规模，应评估每百候选带来的召回收益和范围遵循 |
| [ScholarLoop](https://github.com/124-creator/ScholarLoop) | BM25/稠密/交叉编码器融合；字段级证据核验 | 可复现评测与可信展示完整 | 推荐理由必须回到原始元数据或文本证据 |
| [CG-RAG](https://arxiv.org/abs/2501.15067) | 稀疏、稠密和图结构联合检索 | 图信息不仅用于展示，也参与召回与推理 | 关系图应来自真实引用边，而不是仅按标题相似度绘制 |

## 二、本项目的新定位

研问智搜不再定位为“带大模型的多源论文搜索网页”，而定位为：

> **面向复杂约束查询的预算感知、证据充分度驱动、可核验学术检索 Agent。**

系统由 TRACE-Rank 和 TRACE-Loop 两部分组成：

### 1. TRACE-Rank

融合查询匹配、多路径 RRF、约束覆盖、时间归一化引用影响力、新近性、元数据质量以及 LLM 严格相关性，最后进行多样性重排。

### 2. TRACE-Loop

每轮检索后计算六类过程状态：

1. 当前结果相关性；
2. 主题、方法、任务、领域约束覆盖；
3. 数据源多样性；
4. 多查询/多来源一致命中率；
5. 元数据完整性；
6. 相对原始问题的主题漂移。

证据充分度定义为：

\[
E=100(0.32R+0.25C+0.14D+0.14A+0.10M+0.05(1-G))
\]

其中 `R` 为相关性，`C` 为约束覆盖，`D` 为数据源多样性，`A` 为多路径一致性，`M` 为元数据质量，`G` 为查询漂移。

控制器在以下动作中选择：

- `citation_expansion`：已有高相关种子论文且证据不足，沿参考文献和被引论文双向扩展；
- `query_evolution`：覆盖不足或发生主题漂移，重新规划检索式；
- `stop_sufficient`：证据充分，提前停止，节省 Token 和 API；
- `stop_budget`：达到 API 预算，强制停止并返回当前最优结果。

## 三、相对于现有系统的差异化创新

### 创新 1：无需训练的过程感知检索控制器

PaperScout 通过强化学习获得自适应行为，但训练成本较高。TRACE-Loop 使用可解释的过程状态和预算约束实现类似的动态 Search/Expand/Stop 决策，适合比赛现场和普通笔记本复现。

### 创新 2：复杂查询的“约束满足度”而非泛主题相似度

系统不只判断论文是否谈论同一主题，还分别评估方法、任务、领域和时间等约束，减少“主题相关但不回答问题”的结果。

### 创新 3：召回收益与成本联合优化

每轮记录候选增量、有效高相关论文增量、API 次数、Token 和耗时。后续评测增加 `Recall Gain / 100 Candidates` 与 `Recall Gain / API Call`，避免 PaSa/SPAR 式无边界引文扩展。

### 创新 4：真实引用边和证据边界

OpenAlex 返回的 `referenced_works` 和 `cites` 结果用于构建真实引文边。无法从数据源核验的字段明确标记为待核验，不让 LLM 编造 DOI、作者或引用关系。

### 创新 5：现场可降级

有 OpenAlex/Semantic Scholar Key 时启用完整双向引文扩展；额度耗尽时自动切换 Crossref + 限量 arXiv，算法退化但系统不中断。

## 四、当前已实现

- TRACE-Loop 证据充分度、漂移评估和动作决策；
- OpenAlex 参考文献批量解析；
- OpenAlex 被引论文扩展；
- 引文扩展 API 预算统计和真实边记录；
- OpenAlex、Crossref、arXiv 的低延时降级路径；
- 8 项后端测试通过；
- 首轮 AutoScholarQuery 小样本指标和错误分析报告。

## 五、达到先进水平仍需完成的验证

1. 接入稳定 OpenAlex/Semantic Scholar 配额，运行真正的引文扩展消融；
2. 比较固定两轮、只查询演化、只引文扩展、TRACE-Loop 四种策略；
3. 在 AutoScholarQuery、SPARBench、RealScholarQuery 和 ScholarQuest 子集上测试；
4. 报告 Recall@20/50、Precision、F1、NDCG、候选效率、API 效率和时间；
5. 在公开指标没有证明前，不使用“达到 SOTA”表述，而使用“面向 SOTA 路线设计并完成可复现对标”。
